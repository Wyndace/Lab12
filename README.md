# Документация к Практической работе №4
## Тема: Продвинутое внедрение зависимостей с использованием Hilt

### 1. Общее описание проекта
Приложение представляет собой демонстрацию архитектуры **Clean Architecture** с использованием **MVVM** (Model-View-ViewModel) и **Jetpack Compose**. Основная цель — показать, как библиотека **Dagger Hilt** управляет зависимостями между различными слоями приложения (сеть, база данных, UI, фоновые задачи).

Приложение имеет две вкладки:
1.  **Users**: Список пользователей (загружается с JSONPlaceholder).
2.  **News**: Список новостей (загружается с JSONPlaceholder).

Данные кэшируются в локальной базе данных (Room) для работы в оффлайн-режиме.

---

### 2. Используемый стек технологий

*   **Язык**: Kotlin
*   **UI**: Jetpack Compose (Material3)
*   **DI**: Dagger Hilt (внедрение зависимостей)
*   **Асинхронность**: Coroutines, Flow
*   **Сеть**: Retrofit, Gson
*   **База данных**: Room
*   **Фоновые задачи**: WorkManager
*   **Изображения**: Coil

### 3. Структура и описание ключевых файлов

#### A. Настройка Hilt (DI Layer)

Этот слой отвечает за создание и предоставление объектов (зависимостей) всему приложению.

1.  **`HiltApplication.kt`**
    *   **Аннотация**: `@HiltAndroidApp`
    *   **Описание**: Точка входа в графы зависимостей. Обязателен для работы Hilt.
    *   **Особенность**: Реализует `Configuration.Provider` для настройки `HiltWorkerFactory`. Это позволяет внедрять зависимости прямо в `Worker` (классы для фоновой работы).

2.  **`di/NetworkModule.kt`**
    *   **Аннотация**: `@Module`, `@InstallIn(SingletonComponent::class)`
    *   **Описание**: Отвечает за создание сетевых объектов.
    *   **Методы**:
        *   `provideRetrofit()`: Создает экземпляр Retrofit (клиент для сети).
        *   `provideUserApi()`, `provideNewsApi()`: Создает реализации API интерфейсов.

3.  **`di/DatabaseModule.kt`**
    *   **Аннотация**: `@Module`, `@InstallIn(SingletonComponent::class)`
    *   **Описание**: Отвечает за создание базы данных.
    *   **Методы**:
        *   `provideDatabase()`: Создает экземпляр Room Database.
        *   `provideUserDao()`, `provideNewsDao()`: Предоставляет объекты доступа к данным (DAO).

4.  **`di/RepositoryModule.kt`**
    *   **Аннотация**: `@Module`, `@InstallIn(SingletonComponent::class)`
    *   **Описание**: Связывает интерфейсы репозиториев с их реализациями.
    *   **Важно**: Используется `@Binds` вместо `@Provides`, так как это более эффективно для абстрактных классов/интерфейсов. Это позволяет легко подменять реализацию (например, для тестов).

---

#### B. Слой данных (Data Layer)

Отвечает за получение данных из внешних источников и их хранение.

1.  **`data/repository/UserRepositoryImpl.kt`** (и `NewsRepositoryImpl`)
    *   **Аннотация**: `@Inject constructor(...)`
    *   **Описание**: Реализация паттерна "Репозиторий".
    *   **Логика**: Класс принимает `UserApi` и `UserDao` через конструктор (автоматически через Hilt). Он решает, откуда брать данные (из сети или кэша) и управляет потоками данных (`Flow`).

2.  **`data/local/AppDatabase.kt`**
    *   **Описание**: Описание структуры локальной БД. Содержит таблицы `User` и `News`.

3.  **`data/remote/UserApi.kt`**
    *   **Описание**: Интерфейс Retrofit для выполнения HTTP-запросов (GET).

---

#### C. Слой UI и Presentation (UI Layer)

Отвечает за отображение данных и взаимодействие с пользователем.

1.  **`ui/viewmodel/UserViewModel.kt`**
    *   **Аннотация**: `@HiltViewModel`
    *   **Описание**: Управляет состоянием экрана пользователей.
    *   **Внедрение**: В конструктор автоматически внедряется `UserRepository`.
    *   **Функции**: Преобразует данные из репозитория в `StateFlow`, который "слушает" UI. Переживает смену конфигурации экрана.

2.  **`ui/screen/UserScreen.kt`**
    *   **Описание**: UI, написанный на Jetpack Compose.
    *   **Внедрение**: Использует функцию `hiltViewModel()`, чтобы получить экземпляр ViewModel. Hilt сам находит нужную ViewModel или создает новую.

3.  **`MainActivity.kt`**
    *   **Аннотация**: `@AndroidEntryPoint`
    *   **Описание**: Главная активность приложения. Аннотация обязательна, чтобы в Activity можно было внедрять зависимости (и чтобы работали вложенные `@Composable` с `hiltViewModel`).

---

#### D. Фоновые задачи и ресиверы

1.  **`worker/SyncWorker.kt`**
    *   **Аннотация**: `@HiltWorker`
    *   **Описание**: Класс для выполнения работы в фоне (синхронизация данных).
    *   **Внедрение**: Использует `@AssistedInject` для получения зависимостей (`UserRepository`) внутри Worker-а, который создается системой Android, а не нами напрямую.

2.  **`data/receiver/NetworkChangeReceiver.kt`**
    *   **Аннотация**: `@AndroidEntryPoint`
    *   **Описание**: BroadcastReceiver, который слушает системные события (изменение сети).
    *   **Внедрение**: Поле `workManager` помечено `@Inject`. Hilt инициализирует это поле, как только Receiver будет создан. При появлении интернета запускает `SyncWorker`.

### 4. Схема потока данных

1.  **UI (`UserScreen`)** подписывается на данные из **ViewModel**.
2.  **ViewModel** запрашивает данные у **Repository**.
3.  **Repository** проверяет локальную базу (**Room/DAO**).
4.  Если нужно обновление, **Repository** делает запрос в сеть (**Retrofit/API**), сохраняет результат в БД.
5.  **Room** автоматически уведомляет **ViewModel** об изменениях через `Flow`.
6.  **UI** перерисовывается с новыми данными.

Все компоненты (`Repository`, `DAO`, `API`, `Database`) создаются и связываются библиотекой **Hilt** автоматически на основе модулей.
